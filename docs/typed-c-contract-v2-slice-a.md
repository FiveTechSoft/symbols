# Typed C verify v2, Slice A: no target execution

`python3 tools/typed_c_contract/verify.py --verify-c-contract FILE -w WORKSPACE` is a separate, opt-in entry point. The contract is strict UTF-8 JSON, no duplicate or unknown fields, at most 8192 bytes, with the seven v1 field names and `schema: "symbols.c-repair-contract.v2"`. In v2 the `probe` object retains `{"kind":"single-c-main","timeout_ms":5000}` as a request for an isolated runtime observation. It does not authorize running arbitrary workspace code. This release has no accredited backend: **Linux and Windows both fail closed with `probe_unavailable`; no workspace C is compiled or run.** The v1 preview and its `symbols.c-repair-contract.v1` schema remain static, with the same wire, refusal codes and inert `probe`. Sending a v1 contract to v2, or a v2 contract to v1, refuses `version`.

v2 verifies the contract location, schema, workspace snapshot digest, scope, and source predicates before selecting a candidate. This slice requires the whole workspace snapshot to contain exactly one file, a single allowed `.c` file (other v1-valid workspaces remain v2-ineligible, not malformed). The source must be a closed, ASCII, one-main shape with the one `<stdio.h>` include and either one literal `printf`/`puts` plus `return 0`, or one canonical decimal local `int` initializer with one `%d`/`%i`/`%u` `printf` conversion and `return 0`. Unsupported syntax, preprocessor directives, comments, trigraphs, expressions, extra statements or files cannot enter the probe path. A negative source integer with `%u` is not eligible. Selection uses the release-fixed static candidate generator and considers only tier-4 `answer_literal` or `answer_value` results. A claimed rule name is not enough: v2 checks the exact diff against original source bytes, before/after hashes, source scope/predicates, the complete before/after shapes, a single literal or initializer edit, and goal bytes under that shape. Zero eligible candidates yields `no_eligible_candidate`; more than one yields `ambiguous_candidate`; one yields `probe_unavailable` until the isolated backend passes its separate security gate. No generated edit is applied to the workspace. The workspace is read again after selection; a changed snapshot refuses. The existing static candidate generator runs as an installed trusted binary and inspects source, but never builds the target.

A syntactically valid invocation returns exactly one compact JSON object followed by one LF on stdout and no stderr, exit 0. Its exact top-level keys are:

- `schema`: literal `symbols.c-repair-contract.v2`.
- `status`: `no_eligible_candidate`, `ambiguous_candidate`, or `probe_unavailable` in this slice. Test-injected fake broker outcomes may be `compile_error`, `compile_timeout`, `run_timeout`, `run_crash`, `exit_mismatch`, `stdout_mismatch`, `output_limit`, `infrastructure_error`, or `observed_match`; no such outcome is possible through the production CLI in Slice A.
- `promise`: literal `isolated candidate observation only; not a verified repair`.
- `executed`: whether the target binary started; always JSON `false` in Slice A, not a synonym for broker invocation or compilation.
- `provenance`: literal `operator-supplied/identity-unverified`.
- `contract_sha256`, `workspace_digest`: 64 lowercase hexadecimal hashes of the exact validated contract bytes and checked workspace snapshot.
- `candidate`: null unless exactly one candidate is eligible; then only `rule`, `path`, `before_sha256`, `after_sha256`, `tier` (no diff or source).
- `observation`: null in all production Slice A results. A future isolated backend can supply bounded phase, outcome, complete stdout digest/length, exit status, and pinned platform/compiler/image identifiers. Neither raw stdout nor raw stderr is in this wire.

Invalid contract, location, workspace or snapshot refuses with exit 2, empty stdout and exactly `refused: <reason>\n` on stderr. Reasons follow the v1 closed validation table where applicable, including `version`, `workspace_digest`, and `workspace_changed_during_preview`, plus `invalid_or_unavailable` for unclassified failure. CLI misuse prints usage on stderr and exits 2. Ineligibility is not a refusal or runtime failure.

A later backend must run compiler and binary inside a separately approved disposable, secret-free, networkless VM with host-enforced process, time, memory, filesystem and output limits. The fixed toolchain/image and effective limits belong in the observation. `observed_match` will mean one complete, normally exited run with exit 0 and byte-exact stdout equal to the asserted goal; it cannot prove intent, general correctness, improvement on the original, negative task constraints, portable behavior or permission to mutate. Tests for this slice use fake broker responses injected into the library, never a CLI-controlled backend selector. CI on Linux and Windows tests v1 invariance and v2 fail-closed behavior without running task-supplied C. Actual VM security and runtime testing require a separate Slice B gate.
