# Binary-safe typed C preview v1

`python3 tools/typed_c_contract/binary_preview.py --preview-c-binary-contract FILE -w WORKSPACE` is a separate, opt-in **static** entry point. It never compiles or runs workspace C and never changes the workspace. Input is the existing strict seven-field contract wire except for `schema: "symbols.c-binary-preview.v1"`. `stdout` retains canonical padded RFC 4648 `bytes_b64`, integer `length` (0..127), `termination: "exact"`; the decoder checks both canonical re-encoding and byte count. The new generator receives an in-process Python byte sequence, never a command-line argument or C string. `probe.kind=single-c-main` and `timeout_ms=5000` remain inert. V1 preview and v2 verify are unchanged; cross-schema contracts refuse.

This preview admits exactly one source file and one allowed `.c` path (ASCII source, at most 768 bytes and 32 lines), with no comment, arbitrary include, extra statement, conversion argument, second main, preprocessor choice, or task-specific macros. Recognized originals are a sole `<stdio.h>` include and `int main(void)` with a single `printf("literal")` or `puts("literal")`, then `return 0;`; an already canonical binary candidate is also recognized if it still fits the original-source size cap (longer generated candidates require a later slice for re-editing). Supported literal escapes are `\\n`, `\\r`, `\\t`, `\\"`, `\\\\`; printf can contain `%%` but no other percent conversion. `puts` adds exactly one LF. Invalid or unsupported shapes have zero candidates, never a guess. Existing `answer_value` integer-to-decimal shapes are out of scope. The asserted goal is not proof of semantic intent.

For a nonempty goal the entire body is replaced by a closed form using `static const unsigned char B[] = {0xNN,...};` and `fwrite(B,1,sizeof(B),stdout); return 0;`. The canonical fixed Windows preamble includes `<io.h>` and `<fcntl.h>` behind `#ifdef _WIN32`; immediately before `fwrite`, it checks `_setmode(_fileno(stdout), _O_BINARY) == -1` and returns 1 if the mode cannot be set. POSIX does not need mode switching. A zero-byte goal uses the dedicated `int main(void) { return 0; }`, with no zero-sized C array. The generated source is checked with the same closed grammar and its modeled byte sequence must equal the goal. Hex values are numeric array elements, not C string escapes; adjacent hex digits cannot merge. No claim of byte-exact output follows from the static preview. A separately approved VM probe would be needed for task-supplied C.

Diff construction uses a bound checked on actual UTF-8 bytes: >4096 refuses `candidate_patch_limit`, never truncates. The maximum goal contribution is 127 × 5 + separators = 761 bytes. At the 768-byte/32-line source cap, paths under the shared 511-byte path bound contribute at most 1,050 diff header bytes, and the fixed candidate including mode preamble is under 1,050 bytes; a worst-case 768 + 1,050 + 1,050 + 64 newline/hunk/prefix overhead = 2,932 bytes, below 3,400. The real guard remains binding even if paths, rendering or future formatting change. Snapshot, path/scope, source predicates and race checks from the v1 preview still apply. A source predicate that a candidate would change filters the candidate.

On valid input the JSON fields are `schema`, `status` (`static_candidate_unverified` or `no_static_candidate`), `promise`, `not_executed: true`, `provenance: operator-supplied/identity-unverified`, `contract_sha256`, `workspace_digest`, `candidate_count` and `candidates` (tier 4, rule `answer_bytes`, path, before/after digests and bounded diff). This output contains private source lines: keep it private. A refusal exits 2 with empty stdout and `refused: <reason>` on stderr. Tests compile/run only **our generated candidates from fixed local test fixtures**, including Windows binary stdout, to test the generator itself; these are not Slice B and no user workspace code is executed by the product CLI.
