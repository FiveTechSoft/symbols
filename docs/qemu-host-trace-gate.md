# QEMU host trace gate: fixed boot acceptance criteria before boot

Status: design and offline parser only. This patch does not launch QEMU and cannot set `runtime_complete:true`. The static 49-file ELF inventory from the prior gate is an input, not a runtime pin. The first target is a disposable, secret-free Ubuntu 24.04 GitHub runner with effective KVM permission; the server's installed QEMU `.16` is a different input and must not reuse the `.18` closure. TCG would be a distinct measured mode with a separate fixed argv, accelerator module closure and no silent KVM fallback.

## Trace plan

Before any boot dispatch, freeze the exact tracing command, `strace` executable/package digest, execution image/runner provenance, QEMU binary and kernel/initramfs bytes, loader/environment, fixed QEMU argv, and the source snapshot. Use one child-process trace from first `execve` through clean exit, without late attach. `strace -f -qq -e trace=execve,open,openat,openat2 -s 4096` is a proposed starting observation, not yet a claim that all file dependencies are covered. A separate file-syscall inventory must include `openat2`, `statx`, `newfstatat`, `readlinkat`, `access`, relative dirfds and missing probes or prove why a specific call is irrelevant. Any incomplete, truncated, unparsable or unbounded trace refuses. Test whether QEMU loads accelerator `.so`, firmware/ROM, keymap/data, NSS and loader cache paths. No `sudo` QEMU, secrets, network device, writable share or target-controlled C. Trace collection has explicit wall/output/process limits and cleanup; a marker alone is not success.

The current `trace.py` is a **restricted offline pilot**: it parses only an exact subset of open/exec/exit lines, refuses other lines, ensures observed successful files come from the staging root and match the rootfs inventory bytes, requires every static ELF file to have been observed, and produces `runtime_complete:false`. It does not run or orchestrate `strace`; no output from this pilot can accredit a complete runtime. Its test vectors exercise missing files, hostile/relative paths, partial lines, wrong exit, outside-root reads, SHA drift and an unseen static dependency.

## Future boot gate acceptance, not met by this patch

1. Reproduce fixed kernel, minimal initramfs and QEMU package/ELF closure from authenticated snapshot bytes. Check loader, `dlopen` modules and all effective host-opened firmware/data files against a closed runtime inventory on the host; no ambient file, ambiguous resolution, `/etc/ld.so.cache` fallback or path race. The boot must use the same measured files that were traced, not just matching path names after the fact. An unknown file or unsupported tracing syscall is a blocker, not an ignored event.
2. Commit a fixed KVM command line with no dynamic text except immutable staged file paths: `-M microvm -accel kvm -cpu host -m 128M -smp 1 -kernel <kernel> -initrd <initrd> -append 'console=ttyS0 rdinit=/init panic=1' -nodefaults -no-user-config -nographic -serial stdio -monitor none -net none -no-reboot`. Test real effective `/dev/kvm` access, not a kvm-ok banner. Keep the server TCG command separate and measured if used.
3. Run one fixed boot. Demand the sole `SYMBOLS_BOOT_ONLY_SUPERVISOR_READY_v1` serial marker, self-shutdown and QEMU exit 0 within a finite deadline, bounded output and complete process cleanup. Marker without shutdown, timeout, extra/unknown file open or drift fails. Only after the actual trace and independent host file remeasurement can a separately reviewed gate consider `runtime_complete:true` for that mode and host.

A successful boot would prove only this functional boot path. It is **not** accredited isolation, does not run target C and does not enable Slice B; the adversarial VM security gate remains separate.

## Runner collection proposal (diagnostic, fail closed)

`qemu-runtime-collection.yml` is a separate manual, immutable-commit workflow, not a new CI boot or a launch-eligibility signal. Its three required dispatch values are the 40-hex reviewed commit, SHA-256 of that hosted image's `/usr/bin/strace`, and exact `ImageVersion`. Acquire/review the latter two in a **separate no-boot preflight**; do not guess them from another image or convert a binary observed during this run into advance approval. The workflow checks these before any boot and refuses a changed image or tracer. It then builds the frozen Noble archive from verified snapshot metadata, rechecks archive/manifest/static-closure digests, stages selected snapshot files, makes the fixed minimal initramfs, and opens `/dev/kvm` effectively without privilege escalation. No server `.16` or TCG fallback, no C source, guest network, disk or share. The static closure is a selection seed, not proof that it is exhaustive.

The fixed direct loader command uses `--inhibit-cache` and staged library paths; QEMU gets fixed microvm/KVM argv, fixed snapshot kernel and boot-only initramfs, `-L` staged data, and a minimal environment. Trace starts at loader `execve` with `strace -f -qq -s 65535 -e trace=%file,execve`, bounded to 60 seconds, 16 MiB trace and 64 KiB per output; failure or timeout kills the process group. The marker exactly once (CRLF or LF from serial; bounded kernel messages may surround it), clean exit, and complete log are necessary but not sufficient. The run-local report lists observed successful opens, missing/metadata probes, ambient paths, unsupported syntax count/line numbers, file hashes, absent static files, binary/kernel/initramfs/tracer bytes, exact argv, image identifier and trace hash. Raw serial and raw trace remain run-local and are not uploaded. A one-day report artifact is uploaded even when collection fails. A blocked report exits nonzero by design; a red run with a report is useful measurement, not a host-closure pass.

This collector **never** sets `runtime_complete:true`. A success-looking boot still blocks on ambient cache/NSS/firmware/module paths, unresolved syscall/dirfd/symlink semantics, possible path replacement races and incomplete proof about file-backed mappings. A later gate must explicitly enumerate all file syscalls on the pinned strace version, resolve dirfd/cwd and unsuccessful probes with a closed allowlist, account for kernel-mapped PT_INTERP, prove file identity at use time (not just post-read pathname), and review any required additions to the signed snapshot inventory. This diagnostic cannot promote the 49-file static set on its own. Do not run until exact runner/tracer values and the patch bytes pass review.
