# Slice B guest image pin recipe and empty lock schema

Status: `not yet pinned`. This is a declarative recipe, not an artifact lock or isolation finding. No package/image hash is asserted here. Production v2 remains `probe_unavailable`. The later measured lock must not be accepted by runtime until its separate serialization/verifier gate passes.

## Recipe versus measured lock

This docs-only recipe defines the required lock fields and verifier checks, not a canonical byte serialization or executable verifier. It must not claim that a mutable hosted apt install is pinned. A future lock records actual artifact hashes only after downloading by immutable origin and measuring bytes, then running a clean-room reproduction and rehash. The measured lock, canonical byte serialization and verifier belong to a later byte gate; this document intentionally has no filled lock.

Recipe inputs, each with immutable source URL or content-addressed identifier, exact byte length, SHA-256, architecture and provenance:

- Host QEMU x86_64 executable and its full dynamic dependency closure (loader, shared libraries, QEMU modules/firmware used), plus repository snapshot/package artifact SHA and version. Package names and `qemu --version` alone are not pins.
- Bootable x86_64 kernel **actual bytes** and required modules/config (or prove no modules loaded), kernel cmdline, and source/package provenance. Do not silently select latest `/boot/vmlinuz-*`.
- Static BusyBox init binary, its library closure if not actually static, complete init/supervisor executable/script bytes, UID/GID/device policy and deterministic newc initramfs packing program plus each archive entry path, mode, uid/gid, mtime, order, link target and output digest.
- Guest C toolchain: compiler, preprocessor, assembler, linker, CRT, headers, libc/runtime, dynamic loader if needed, default search paths/spec files and plugins. Pin input bytes, fixed compiler/link flags and their versions. A command name, version text or apt meta-package does not close the toolchain.
- Build environment: builder container image **digest** rather than tag, base OS/repository snapshot, artifact fetch policy (TLS and no redirect to mutable location), build command/script bytes and expected output SHA-256. Distinguish host QEMU dependencies from guest compiler dependencies.

At boot the controller remeasures the host-side kernel, initramfs and QEMU/dependency closure from opened file descriptors or content-addressed staging copies before QEMU launch, rejects path/size/hash drift and races between verification and use (fd-backed or immutable staging). The guest supervisor may remeasure its own compiler, sysroot, BusyBox, executable and expected guest image manifest before compiling even a fixed fixture, and report observed digests over the private bounded supervisor channel. The host compares that report to the lock as a consistency check, but a compromised guest could lie; authoritative trust comes from host-verified immutable input-image bytes, closed inventory and independent review. Missing/inconsistent/failed checks are `infrastructure_error`, never `observed_match`. Guest self-report does not prove isolation. A missing kernel/QEMU/guest binary pin, wrong digest, changed command line, incomplete dependency closure or unverifiable measurement refuses before fixture execution with `pin_unavailable`/`pin_drift`/`pin_incomplete` in the image builder/controller; if wired to the v2 observation seam, map to `infrastructure_error` with phase `broker`, never a stdout mismatch. Distinguish host preflight from guest checks, and do not log raw hostile source/output.

The lock should enumerate a sorted, closed file inventory with normalized POSIX paths, byte sizes and SHA-256, no duplicate paths or symlinks escaping an image root. Include schema/version, architecture, all URLs with immutable digest/transport identity, exact build command, an initramfs SHA-256 and a digest over its canonical serialized lock. Refuse unknown keys, missing dependencies, hash mismatches, volatile URLs, mutable package resolution, wrong architecture, extra file, nonreproducible image bytes or changed runtime measured output. The specific lock serialization and verifier need their own small reviewed byte gate before any trusted runtime uses them. Keep artifact bytes out of git if large, but publish a checked content-addressed reference, not a bare URL. If provenance cannot be verified, stop; do not mark a record pinned just because its hash was observed once on a hosted runner.

## Lock field schema, not canonical serialization

This recipe fixes the information a future versioned lock must carry, but **does not** fix JSON/binary serialization, field order, canonical digest bytes or a verifier implementation. Those are separate reviewed work before a lock can activate a VM. Required top-level fields: `schema_version`, `architecture`, `state` (`not_yet_pinned` or `pinned`), `acquired_at_utc`, `review_by_utc`, `builder_image_digest`, `builder_command_digest`, `kernel_cmdline`, `qemu_fixed_argv_digest`, `compiler_flags_digest`, `files`, `initramfs_sha256`, `image_id`, `provenance`. `files` is a closed sorted inventory: each record has stable role (`host_qemu`, `host_dependency`, `guest_kernel`, `guest_busybox`, `guest_supervisor`, `guest_toolchain`, `guest_sysroot`, `builder_input`), normalized relative path, byte length, lowercase SHA-256, immutable source identifier, signature or authenticated metadata evidence where available, source snapshot identifier, license and dependency links. `provenance` records signatures and upstream support/advisory channels. The specific byte encoding and digest coverage for these fields remain an explicit blocker until the serialization gate. A `not_yet_pinned` lock is descriptive only and cannot be passed to a VM controller; no empty hashes, pseudo URLs or magic "TBD" values masquerade as measurements. No filled lock is present in this commit.

## Pin renewal and expiry

A lock is immutable once reviewed. Record acquisition timestamp UTC, upstream support/EOL and security-advisory channels for each kernel/QEMU/toolchain/BusyBox component, an explicit `review_by` UTC date and a release-specific permitted image validity window. For evaluation set `review_by` no more than 30 calendar days after acquisition; re-evaluate sooner on a relevant CVE, revoked source/signature, upstream EOL, or runner-image change. Expired/unknown `review_by`, or a relevant untriaged vulnerability, blocks *new fixture runs* with `pin_expired` or `pin_review_required`; no automatic apt update or silent acceptance of old binaries. Renewal creates a new versioned lock with newly acquired bytes, independent signature/provenance and hash verification, two clean reproducible builds, boot remeasurement and fixed-fixture CI, and its own byte gate. Preserve previous lock, artifacts and run evidence for audit; record migration rationale and invalidate stale image/cache identifiers. Any change to compiler flags, dependency closure, supervisor, kernel or QEMU counts as a new pinned image ID and needs review; do not reuse prior isolation accreditation or tests by implication.

## CI and safety scope

This docs-only commit introduces no executable CI or lock example and relies on the existing CI workflow; a later schema/verifier gate should add positive and negative fixture tests without downloading packages or running C. CI for a future locked build must fail closed on missing cache/network rather than falling back to apt latest; secret-free disposable job, `permissions: {}`, no privileged PR trigger, no target-controlled source passed to host compiler/shell, no QEMU launch in this commit. Keep independent adversarial VM review and cgroup enforcement in the later security gate, not a claim from artifact pinning.
