# Slice B builder rootfs reproducibility gate (design, not a boot image)

State: proposed. Snapshot `20260927T000000Z`; 128 previously measured candidate packages (146,235,932 B) plus exactly 14 Noble builder packages (8,116,208 B): 142 `.deb`, 154,352,140 B. The signed snapshot indexes and package rows must be embedded as a separately reviewed, immutable input manifest with expected SHA-256, size, architecture and URL. A workflow that merely checks a manifest's self-asserted hashes without verifying its signed-index provenance does not close this gate. The source acquisition already found three `InRelease` and twelve Packages/Sources index hashes. Missing `Valid-Until` was a parent-approved bounded exception, not a field invented in the archive. Renewal must recheck relevant CVE, signing key, EOL and runner image changes.

## One rootfs job, repeated independently

Each job checks out an exact reviewed commit SHA without persisted credentials, no repository write permission, no secrets and no `apt install`. The code and manifest are reviewed by hash before dispatch. Jobs re-verify the Ubuntu archive signature with a pinned signing-key fingerprint (not a key downloaded ad hoc), then each `Packages.xz` digest against the signed InRelease, and each of the exact 142 package rows. Fetch only the snapshot HTTPS package paths with redirects disabled and per-object/total size ceilings. SHA-256 and byte length must match before any archive parsing. A mismatch, missing key, expired policy, changed dependency, unsupported runner or network failure aborts; no fallback to latest packages or previously unverified cache.

Parse ar/control/data.tar only after byte verification. Never run package scripts, `dpkg -i`, host compiler, QEMU or target C. Reject path traversal, device/FIFO/socket, setuid/setgid except the **exact eight approved account/PAM paths** which are recorded with package and payload SHA but not materialized, duplicate path with conflicting contents/type/mode/target, symlinked parent traversal and symlink escape. Repeated directory rows must have compatible mode and type and dedupe to one. File links are interpreted inside an image-root namespace, never followed into host root during extraction. Install regular files through safe no-follow/openat-style APIs or extract into an isolated prevalidated staging tree; no generic `tar -xf` across untrusted absolute links.

Absolute symlinks permitted only as the three exact package/path/target tuples in `tools/builder_rootfs/policy.py`:

- `libpython3.12-minimal: usr/lib/python3.12/sitecustomize.py -> /etc/python3.12/sitecustomize.py`: MUST materialize in the candidate rootfs; its target `etc/python3.12/sitecustomize.py` must exist as a hash-verified regular file from the same package. The preceding local host scratch extraction omitted the link deliberately and is not the image-assembly rule.
- `tar: etc/rmt -> /usr/sbin/rmt`: omit, optional dangling link. The `tar` executable has a textual `/usr/sbin/rmt` reference; this is accepted only for fixed extractor argv that never invokes remote archive names or `--rmt-command`.
- `tzdata: usr/share/zoneinfo/localtime -> /etc/localtime`: omit, optional configuration.

Every other absolute link is refused, including paths with `..`. Negative tests cover unexpected package, changed target, missing sitecustomize target, symlink parent, path traversal, setuid and special file. The production extraction implementation needs complete recorded entries, not merely the pure-policy tests added here. Omission of the two optional links and the eight account helpers must be represented explicitly in the artifact manifest and review; no silent omissions. For the candidate root, hash every regular file and record every directory mode and symlink target, sorted by canonical path. Compare actual filesystem inventory to expected rows with no extras.

## Compare gate and limits

Two separate clean Ubuntu 24.04 hosted jobs, `permissions: {}`, each independently fetch and assemble the exact candidate root. Each exports a canonical sorted inventory (`path`, type, normalized mode, size, SHA-256 or link target, source package/SHA) and deterministic archive: fixed member order, path, type, mode, uid/gid=0, mtime=0, link target, and no host metadata. A third job downloads both run-local artifacts and compares the raw archive bytes (`cmp`), length/SHA-256 and inventories; fail on any difference. The archive must not include builder secrets, Git metadata, host device nodes, active symlink to host `/`, or executable target-C input. Artifacts are candidates with short retention, not a pin or a signed provenance receipt. The two jobs using the same hosted image and same script are an independent-run consistency check, not independent toolchain provenance.

This rootfs is NOT bootable and no initramfs/supervisor/kernel/QEMU is built or launched here. `verify_lock.py` remains evidence-only and denies launch. A separate gate must specify initramfs contents, init, supervisor, exact fixed QEMU argv, host runtime-open closure and compiled fixed fixture; security accreditation and arbitrary C remain later gates. No checkout of a mutable ref may be interpreted as an immutable build identity.
