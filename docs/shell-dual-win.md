Base832ccae01b41dc66a249a59ba85ddf0ed985a815. Design only, no implementation.
Current test_agent_shell.c Windows Test9 writes O then E in one PowerShell loop.
It proves interleaved drainage, not two independent writers. Audit criterion2
remains partial for exactly this distinction. Production already drains both
pipes; no production change proposed and no efficacy run.

Add a Windows-only C helper executable and dedicated test. Helper uses two
CreateThread workers, a shared start event and a two-party ready handshake.
Each worker owns one inherited standard handle; after both are ready parent
sets the event. Worker stdout writes exactly100000ASCII O bytes, worker stderr
100000E bytes through WriteFile loops supporting partial writes. Wait for both,
require exact totals, return0. No CRT console Unicode or PowerShell buffering.
Concurrent here means two independently scheduled writer threads released from
a common barrier, not that CPU execution is simultaneous or every write overlaps.
Parent/test/helper time limits prevent a bad fixture from hanging forever.

path supplied by CTest TARGET_FILE, known temporary working directory and fixed
command suffix (no arbitrary external content). Test asserts return1,exit0,

## Implemented scope

No production file changed. `test_shell_dual_win` is registered only on Windows,
not as a passing Linux stub. The helper has two native writer threads, separate
ready events and one shared release event. Sensitivity modes change only the
fixture's generated bytes, never the oracle. A nonzero mask on the normal mode
is a red, not grounds to increase the timeout or relax totals/purity.
Linux cannot supply native Windows evidence; native evidence remains pending
until exact-SHA MSVC and ASan logs show the real test running and passing.
