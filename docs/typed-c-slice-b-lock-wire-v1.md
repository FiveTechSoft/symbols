Production broker remains unavailable. ## Canonical encoding

Choose a two-layer format so the on-disk lock cannot silently change via JSON formatting: `SBL1` (ASCII, 4 bytes), u32 big-endian canonical JSON payload length (4 bytes), payload bytes, and SHA-256 of all preceding bytes (32 raw bytes). Total = 40 + JSON length. Upper bound 4 MiB total, refuse declared length > 4 MiB-40 before allocation; stream reader must bound actual bytes and demand EOF, no second frame. The trailing digest detects accidental corruption, not hostile forgery/authentication.

Canonical JSON: UTF-8 without BOM, `ensure_ascii=True`, no insignificant whitespace, sorted keys at every object level, separators comma/colon, `allow_nan=False`, ASCII-only payload bytes. No duplicate keys at any nesting level, no floats, no booleans in integer slots, no unpaired Unicode surrogate, no leading-zero or noncanonical integer representation, no unknown fields; parse then re-encode and demand byte-for-byte equality. Reject trailing JSON, changed digest, missing field, extra field, wrong order, wrong type, wrong schema, truncated frame and trailing byte with closed refusal codes. Key-ordering is codepoint/ASCII; all keys in schema below are ASCII. Use Python standard library pure byte functions and explicit `object_pairs_hook` duplicate rejection. No shell, filesystem, network or VM call in parser.

Top-level **exact keys**: `architecture`, `builder`, `exclusions`, `files`, `image`, `packages`, `provenance`, `review_by_utc`, `schema`, `snapshot_id`, `state`. Schema literal `symbols.slice-b-lock.v1`, architecture `amd64`, snapshot ID exactly `YYYYMMDDTHHMMSSZ` validated date, state either `measured_payloads_only` or `pinned_image`. `review_by_utc` is null only while measured-only; pinned state requires UTC RFC3339 seconds and <= acquisition time + 30 days. An expired date refuses new run (`pin_expired`) and relevant CVE/signature revocation/runner change is a separate `pin_review_required` external check, not a parser inference.

`packages`: sorted unique package names/versions, each record with exact keys `name`, `version`, `architecture`, `pocket`, `filename`, `size`, `sha256`, `source_name`, `source_version`, `source_index_sha256`; size integer 1..200000000, lowercase 64-hex digests; relative normalized repository path. Full signed snapshot chain and matching fetched bytes are supplied as trusted expected context and compared outside parsing. `files`: sorted unique POSIX relative paths, each record exact keys `path`, `origin_package`, `type`, `mode`, `size`, `sha256`, `link`. Type `file` or `symlink`; mode u16 permissions, no setuid/setgid; file has nonnegative size+64-lowercase-hex SHA and null link, symlink has null SHA/size and a normalized in-root relative link. Directory inventory is a separate verified input, not silently omitted from the image closure. Reject path traversal, absolute path, duplicate, symlink parent escape, device, FIFO or setuid/setgid. Record-count caps and byte budget must be fixed in implementation at least 128 packages and 5283 files; propose 256 packages, 10000 files, 1 GiB expanded bytes.

`exclusions`: exactly sorted set of eight `{package,path,reason}` triples as established in the measured scan, reason literal `setuid account-management helpers; guest runtime has no auth flow or account management`; no wildcard or extensible allowlist. The verifier refuses any extra setuid/setgid found in raw package inventory or any excluded path reappearing in final image. The raw inventory itself is external trusted measurement to bind; neither lock nor guest claim alone proves it.

`builder`: exact keys `state`, `extractor_sha256`, `readelf_sha256`, `loader_closure_sha256`, `source_inventory_sha256`. For measured-only state, `state=unverified` and nullable hashes; for pinned state, all must be measured and bound to a separately verified closed bootstrap image. `image`: exact keys `state`, `kernel_sha256`, `qemu_sha256`, `busybox_sha256`, `initramfs_sha256`, `supervisor_sha256`, `image_id`, `qemu_argv_sha256`, `compiler_flags_sha256`. Measured-only allows null only for not-yet-built fields, but requires measured kernel/QEMU/BusyBox hashes if it claims them; pinned state requires every field and host remeasurement. `provenance`: exact keys `signing_fingerprint`, `inrelease_sha256` (three-pocket exact object), `packages_indexes_sha256` (closed sorted list), `sources_indexes_sha256`, `acquired_at_utc`, `valid_until_policy`, `crosscheck_preflight_run`. The preflight crosscheck is corroboration, not an authorization or substitute for signed package hashes. All object/array nested shapes and caps must be fixed in code before any parser is wired to a controller; otherwise refuse.

Critically, a valid parsed `measured_payloads_only` lock **cannot launch**, compile or produce `observed_match`; a valid `pinned_image` lock still requires actual artifact rehash, signed-chain check, image bytes, limits, guest separation and later security accreditation. Parsing is not a policy gate by itself. The current evidence lacks closed builder, initramfs/supervisor, image ID and observed dynamic file-open closure. Thus only measured-only fixture vectors can be made honestly now, and tests must assert launch denied. Do not invent placeholder hashes for a pinned fixture.
