# QEMU host static closure candidate, not a runtime pin

The `tools/qemu_closure` prototype reads the **existing candidate rootfs archive and inventory** from the signed Noble snapshot of 2026-09-27. It does not execute QEMU, compile C or boot a VM. It rehashes the whole archive, resolves only in-inventory relative symlinks, checks package digests against the frozen source manifest, parses ELF64 x86-64 `PT_INTERP` and recursive `DT_NEEDED`, and compares each reached file's bytes to its inventory size and SHA-256. It refuses RPATH/RUNPATH, ambiguous library lookup, missing dependencies and changed bytes. Output is sorted deterministic JSON with `runtime_complete:false`.

Measured local candidate: `usr/bin/qemu-system-x86_64` from `qemu-system-x86` version 1:8.2.2+ds-0ubuntu1.18, binary SHA-256 `8a35ccba41582fc6c38b9df85fc9e35fa1d42f414d2d7d8090ee9b2f5e7c0854`; static closure reaches 49 regular files, 52,770,072 bytes total, manifest SHA-256 `7659770a9649b3907a8715188e550e368d4c3ef889e4b467ff9c2bcba7329b57`. This is a static dependency candidate **only**. It does not pin the loader's runtime resolution policy, NSS, indirect `dlopen`, QEMU plugin/module selection, firmware, data, or all files opened by a boot. The Ubuntu signed-index/DEB verification of the input tar is a separate prerequisite, not repeated by the static closure command's manifest lookup. The input tar is 420 MB and is **not** an initramfs; the boot-only initramfs is 2,126,260 bytes SHA-256 `21d1a476d2e561c4d6f506b198b401772d3600a6d16ef2398e023612cf3ae38d`.

Next gate: trace one fixed boot on a secret-free disposable host, record every actual QEMU-loaded ELF and opened module/firmware/data file, and reconcile to a closed signed-snapshot inventory plus runtime host measurements. Require exact version, digest, and host loader behavior before calling the host closure pinned. KVM on GitHub's runner is the first target. A second server currently has QEMU 1:8.2.2+ds-0ubuntu1.16, **not** this .18 binary; it needs its own source package and closure and currently lacks effective `/dev/kvm` access for the `antonio` user. If a TCG mode is used, it has its own fixed argv and measured closure including its accelerator module. No mode silently falls back from KVM to TCG. The fixed boot marker, self-shutdown, exit status and deadline belong to a later boot gate. A passing boot shows boot functionality, **not accredited isolation**. Slice B remains `probe_unavailable`; arbitrary candidate C and target compilation are not in this gate.
