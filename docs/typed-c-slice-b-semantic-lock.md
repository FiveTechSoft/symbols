# Slice B measured lock semantic verifier

This change adds only a pure in-memory `verify_lock.py` and tests. It does not wire production `verify.py`, create an initramfs, launch QEMU or accredit isolation. The existing `SBL1` parser verifies framing/canonical JSON, not an authoritative lock.

## Input provenance and state

Fixture `tests/typed_c_measured_lock.sbl1` was built from the signed Ubuntu Noble snapshot `20260927T000000Z` audit records, after byte-verifying 128 `.deb` payloads (146,235,932 compressed bytes) against `Packages`, streaming and filtering 6,782 entries, and rehashing 4,652 retained regular files. It contains exactly 128 package records, 5,283 non-directory rows, 698 unique directories, eight excluded setuid/setgid paths, 12 Packages and 12 Sources index digests, the three signed InRelease digests, and actual kernel/QEMU/BusyBox hashes. SHA-256 of complete SBL1 fixture: `52dd50f15f0c5638a02ef5b750ad756a07ed7925281dfb36606c2af474b978b8`; frame length 1,218,485 bytes, under the unchanged 4 MiB cap. The audit JSON records are evidence, not accepted as runtime lock bytes.

The fixture's state is `measured_payloads_only`, builder `unverified`, image `not_built`. The semantic verifier returns only `validated_evidence_only`, `launch_eligible=False` for matching context. No `pinned_image` state can pass the current verifier, because the builder closure, initramfs, supervisor and runtime-open proof do not exist. It refuses `pin_incomplete` even if a caller fills plausible hashes. This is a conservative gate, not a feature toggle.

## Closed schema and precedence

Exactly 12 sorted top-level keys: `architecture`, `builder`, `directories`, `exclusions`, `files`, `image`, `packages`, `provenance`, `review_by_utc`, `schema`, `snapshot_id`, `state`. All nested keys closed in `verify_lock.py`; types checked exactly (`bool` is never an integer), normalized relative paths, sorted unique records, no symlink-parent paths, and caps of 256 packages, 10,000 total file+directory paths, 1 GiB expanded file bytes, 4 MiB SBL1 frame. Directories include all 698 unique paths and modes; repeat directory entries in packages must agree. No sidecar, no Merkle, no silent omission.

Error precedence: SBL1 magic/length/truncated/trailing/digest, then JSON duplicate/noncanonical, then all schema fields, then types/caps/order, then context binding, then exclusions/setuid, then state/freshness. `verify_lock.py` handles the semantic stages only; frame/JSON precedence belongs to `lock_wire.py`. Context is provided from independently authenticated/rehashed audit data by a later caller, not from the lock itself. Tests inject matching context to prove the pure verifier and mutate fields to prove refusal; they do not establish the provenance of that context on their own.

The eight exclusions are exact `(package,path)` pairs, with reason `setuid account-management helpers; guest runtime has no auth flow or account management`. Raw package setuid scan must show exactly those eight and final image must contain none; any ninth is a refusal. The measured fixture records excluded account/PAM helpers but has not run a guest to prove no auth flow. Missing `Valid-Until` is recorded as `no_expiry_field; freshness_enforced_by_review_by`, an explicit parent technical freshness decision. A future pinned image would require an acquisition UTC timestamp, `review_by <=30 days`, and early review for CVE/EOL/revoked signature/runner change, but this verifier denies all pinned launches regardless. Kernel/QEMU/BusyBox bytes coincide with hosted KVM preflight #4 (https://github.com/FiveTechSoft/symbols/actions/runs/36406181849/job/108875367605) as cross-check, not substitute for signed snapshot chain.

## Deferred

The current caller does not yet remeasure closed builder loader/interpreter/extractor/readelf/Python dependency bytes. The 14 extra Noble bootstrap `.deb` packages are metadata candidates only, +8,116,208 B; no new payload was downloaded for this code change. A later independent gate must verify and scan those packages, pin builder tools, repeat extraction in a clean builder and byte-compare; then a separate double image build. QEMU dlopen/firmware and GCC specs/sysroot/runtime-open closure, host-enforced limits, guest UID/channel separation and adversarial isolation tests remain later gates. `verify_lock.py` accepts no external content as authorization to start any of them.
