# Project rules and evidence record

The test counts below are historical results from the dated runs, not evidence that the current SHA's entire matrix is green. Implementation boundaries are in [README sections 6-7](README.md). The recent pilots have their own contracts in `docs/abstain-and-ask.md` and `docs/ast-inspect.md`. No finite fixture result proves zero hallucinations, fixed latency, general autonomous engineering, or correctness for arbitrary input.

## Phase 4: query canonicalization

`CanonicalizeQuery` in `src/bible_chat.c` normalizes punctuation and flags, splits `del` into `de + el`, and detaches possessive `'s` under G1/G2/G3/G5. The dated run had 26 questions, 10 gains, two intended flips, no hallucination in that battery, CTest 48/48 and an identical second-run MD5. G1 topic and G2 stop-set use functional classes, not specific entity names. This is a tested design constraint, not immunity to every language variant.

## Agent tool tables, Step 1

`ToolInit()` reads declarative `allow`/`contract` rows from `data/agentic/tools.tsv` once, falling back to compiled rows when no valid file rows exist. Malformed rows, unknown TYPE and overflow are rejected with warnings; file order sets priority. The historical September 18 checks were CTest 57/57, six byte-identical batteries, no-TSV fallback and idempotence.

## OpenCode tool-calling integration

`symbols_server` implements an OpenAI-style `/v1/chat/completions` tool-calling subset: it reads tool schemas and `role: "tool"` returns, emits tool calls and a Markdown stop response in the tested flows, alongside direct factual queries. STRIPS plans are bounded by implemented operators and available tool mappings; no optimality or general task-resolution guarantee follows. September 20 checks included a 31/31 server test and an eight-turn real-socket HTTP integration test.

## Phases 7-10: diagnostics, lexical graph, patch harness and indexer

- Phase 7: `agent_diagnose.c` parses selected GCC, Clang and MSVC terminal diagnostics, including location, taxonomic categories, suggestions and a `CodeGraphGetFunctionFile` link; it can activate a replan predicate in covered flows. Historical dedicated tests were 39/39. It does not prove that all compiler failures are diagnosed or cured.
- Phase 8: `code_graph.c` extracts lexical symbols, classes, imports and approximate call relationships from C and selected Python/TypeScript/JavaScript extensions, and traverses dependencies for a heuristic blast radius. This is **not** a native semantic AST for those languages. Historical polyglot tests were 38/38, with no regressions in the 53 earlier C tests.
- Phase 9: `swe_bench_harness.c` exercises patch preflight, local apply/rollback and impact heuristics against repository fixtures named Django, Flask, Sympy, Scikit-learn and Pytest. Historical dedicated tests were 36/36. The rollback is not a production-grade filesystem/Git transaction; fixture checks are not upstream SWE-bench resolutions or a universal corruption/latency guarantee.
- Phase 10: `CodeGraphIngestDirectory` recursively filters common build, VCS and virtual-environment directories and indexes compatible selected repositories. `symbols-agent` offers `--blast-radius`, `--diagnose` and bounded task commands. Its historical indexer test and OpenCode HTTP dogfood run are evidence for those flows, not arbitrary-project indexing within a fixed time or a general autonomous programmer.

## Phases 11-13: shell, C corpus and CTest hygiene

- Phase 11: `agent_shell.c` supports native command execution on tested Windows and POSIX shells, bounded stdout/stderr capture, timeout handling and latency telemetry. `AgentRunnerSolveTask` can feed failed build/test output to the diagnostic parser and attempt local rollback in its implemented flow. Historical shell tests were 57/57; no universal millisecond timeout accuracy or transaction guarantee is claimed.

The C synthesis fixture flow compiles selected modules with GCC and `-Wall -Wextra -Werror`, executes them and may diagnose compiler failures. There is no worst-case O(1) lookup or fixed compilation-time claim. Historical tests were 43/43, with 12/12 agent suites green.
- Phase 13: CTest fixes covered `test_composite` (structural question relations and unresolved pronouns), `test_textlex`, five synthetic-model subsystem tests and nine optional Wikipedia-model tests that skip with code 77 when the model is absent. The September 20 `build-gcc` run recorded 61 passed, nine skipped and zero failed out of 70, not 70 fully exercised tests.

## Phases 17-18: episodic TSV and binary/mapped commonsense

- Phase 17: `episodic_memory.c` stores `(subject, relation, object, source, timestamp)` in a TSV, loads it on startup, checks duplicates by **linear scan**, and exposes supported `/learn`, `/memory` and `/forget` interactions. Its saved file is rewritten non-atomically; append does not propagate every save error, and clearing storage does not prove an already injected live-graph fact was purged. The historical five dedicated tests and 66 passed/nine skipped global CTest runs cover particular cases, not durable verified engineering memory.
- Phase 18: `commonsense.c` saves/loads a binary graph and maps files with POSIX `mmap` or Windows `MapViewOfFile`; headers, lengths and checksum are checked in tested corruption cases. Mapping need not parse source text at that step, but there is no general microsecond or sub-millisecond cold-start guarantee. The historical commonsense suite counted 75 assertions, and global CTest recorded 66 passed and nine skipped of 75.
